# raw/ —— 不可变原文层

## 规则

1. **只增不改、只增不删。** 原文一旦入库，永远保留。发现问题不要编辑原文件，而是新增一份修订版（`xxx-v2.md`）或加一份更正说明。
2. **Wiki 是可再生的编译产物。** `raw/` 才是真源。任何时候发现 Wiki 编歪了，正确动作是**重新编译**，而不是在 Wiki 里打补丁——打补丁会让编译产物逐渐偏离真源且无法重建。
3. **原文要带来源元信息。** 建议每个文件顶部写清：

```markdown
---
来源：<URL / 书名 / 会议名 / 系统导出>
获取时间：YYYY-MM-DD
作者/发言者：<谁说的>
覆盖范围：<时间跨度、版本、地区>
---
```

4. **不要在这里做摘要或重写。** 摘要是编译层的活（`wiki/`）。原文层混入加工内容，就失去了"可回查"的唯一价值。

## 目录建议

```
raw/
├── docs/        # 文档、手册、政策原文
├── chats/       # 聊天记录、会议纪要
├── media/       # 视频/播客的逐字稿（媒体原件另存）
├── code/        # 提交记录、issue、PR 的导出
└── external/    # 外部资料（论文、竞品、报告）
```

## 为什么这一层不能省

蒸馏是**有损压缩**，Wiki 编译也是**有损重排**。如果 raw 层丢了，两层失真就会叠加且**无法追溯与回滚**——你会得到一个看起来很权威、但没人能验证的知识库。保留 raw 是整套结构的最后一道保险。
