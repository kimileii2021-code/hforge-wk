## 6. 下钻契约（何时必须查 Wiki）

> 模板里最关键的一节。**没有它，agent 会用本文件里的印象硬答。**

### 必须查（禁止凭记忆回答）

- 涉及**数字、金额、日期、期限、比例** → 必须引用 `wiki:topics/<id>#<anchor>`
- 涉及**条款、口径、定义** → 同上
- 本次结论与上次不一致 → **停下来报告**，不要自行选择

### 什么时候不必查

- 纯流程性判断，且已在本文件第 2 节判定表覆盖
- 不涉及任何具体事实的取舍

### 查询预算

- 单次任务最多读 **3** 个 Wiki 条目
- 每个条目**先只读 TL;DR 摘要块**；摘要不足以回答 `open_questions` 时才读正文
- 超过预算仍无答案 → 在输出里标注缺口，**不要猜**

### 引用格式

必须带稳定 ID + 锚点粒度（不要写"《XX 政策》那一节"，标题会改）：

```
依据：`wiki:topics/<id>#<anchor>`
```

## 7. 冲突规则

- **事实**（数字 / 条款 / 日期）以 **Wiki** 为准。
- **判断**（怎么权衡、怎么选）以 **本 Skill** 为准。
- **两者冲突时：停下来报告冲突**，贴出两边原文与出处，不要自行裁决。

## 8. 输出格式

每次输出必须带这三块：

1. **方案**：<做什么、为什么>
2. **open_questions**：还没核实、且会影响结论的点（没有就写「无」）
   - 格式：`[open] <问题> → 去 wiki:topics/<id>#<anchor> 核实`
3. **falsifiers**：什么证据会推翻本方案（没有就写「无」）

> `open_questions` 是交给 Wiki 步骤的**任务清单**；`falsifiers` 用来防止"先有方案、再去 Wiki 找支持"的**确认偏误**。这两块是这套结构里最容易被省掉、也最不该省掉的部分。
